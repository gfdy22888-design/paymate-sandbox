# CheckoutLab — Devpost draft (not submitted)

## Elevator pitch

A small, offline learning lab that makes the boundary between a machine-learning suggestion and an authorized transaction visible and testable.

## Primary track

Education.

## Inspiration

Students experimenting with agents need a concrete way to see why a plausible model prediction must not automatically authorize a consequential action. A mock checkout provides a compact state machine with clear failure cases, without using real money or collecting customer data.

## What it does

CheckoutLab exposes a tiny multilingual Naive Bayes classifier trained from 21 explicit, synthetic teaching examples. Students can inspect a suggested product class, its matched features and score separation, or see the model abstain. This is a statistical toy model, not an LLM or a measured production classifier.

A participant can explicitly choose a model suggestion to create an unconfirmed, quantity-one draft, or use the separate strict order parser. A server recomputes prices in integer cents against a fixed seven-item catalog, checks quantity limits, and requires distinct human confirmation and mock approval before capture. It rejects unsupported requests, isolates orders by browser session, and returns the same result for repeated capture. Default payments are prominently marked MOCK.

## How we built it / AI disclosure

The initial PayMate Sandbox code and tests were generated by QwenPaw using glm-5.3-flash. Codex reviewed the implementation, identified defects and requested fixes, then implemented the local learning model, educational interface, regression checks and submission materials. The human participant requested the autonomous workflow and low-resource operation. This draft does not claim the participant personally wrote or reviewed the code, or invent their personal learning experience.

The app uses Node.js built-ins (HTTP and SQLite). The default educational model makes no external API calls, requires no model download and has no npm dependencies. The synthetic examples are part of the source; no real user dataset is claimed.

## Challenges

The agents corrected silent quantity clamping, ambiguous substring matching, repeated adapter calls during concurrent requests, client-supplied price trust, output escaping and request-origin checks. The regression tests record those observable behaviors. Their fixture results do not establish general model accuracy or production payment safety.

## What was learned

The development trace illustrates how to separate probabilistic suggestions from deterministic validation, use explicit authorization states, and test idempotency. Before final submission, the participant should review the project and describe only their own actual learning. No first-person learning claim is supplied on their behalf.

## Next steps

Broader teaching examples, accessibility and classroom usability evaluation, and an optional externally hosted model after its cost and privacy conditions are understood. PayPal Sandbox and external LLM adapters remain optional and unverified; neither is required for this offline educational demonstration.
