# Competition workflow — CheckoutLab

This file is an execution checklist, not a scheduled automation. A GitHub push is not a completed contest entry.

1. Select a contest and read its official rules; keep sources, dates and assumptions separate.
2. Check participant eligibility privately. Do not commit identity, residence, age, account identifiers or credentials to this repository.
3. Build and test in one environment at a time. Use the offline model and MOCK adapter by default; do not download large models or enable paid services implicitly.
4. Review code, rerun the relevant regression suites, inspect the demo and document exactly what was verified.
5. Commit the reviewed changes together and push with Git. Verify a fresh clone and the CI result. Never upload the workspace wholesale or force-push unrelated history.
6. Prepare the Devpost description, source link, truthful AI attribution, demo video and the separate Demo Day requirement. Keep uncompleted account steps explicit.
7. Obtain the participant's real account authorization and action-time acceptance of contest/platform rules where required; never invent identity, signatures or personal learning claims.
8. Submit only after every required field and link has been checked. Record the actual confirmation or project URL; do not equate a draft with submission.
9. Follow any required Demo Day presentation instructions. This event is not finished merely because a submission form was saved.
10. Stop this project's test servers and close its test pages. Verify a complete backup before deleting disposable test artifacts. Preserve the gateway, QwenPaw, credentials, source history and the only backup.
